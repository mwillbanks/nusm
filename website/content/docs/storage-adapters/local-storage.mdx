```ts
import { createLocalStorageAdapter, createNusmStore } from "nusm";

const preferences = createNusmStore(
  { density: "comfortable", theme: "system" },
  {
    adapter: createLocalStorageAdapter(),
    persist: { strategy: "entire" },
    storeId: "preferences",
    sync: {
      validator: (candidate) =>
        typeof candidate === "object" &&
        candidate !== null &&
        typeof (candidate as { density?: unknown }).density === "string" &&
        typeof (candidate as { theme?: unknown }).theme === "string",
    },
  },
);
```

## Options

```ts
interface StorageAdapterOptions {
  storage?: StorageLike;
  prefix?: string;
  serialize?: (value: unknown) => string;
  deserialize?: (raw: string) => unknown;
  pacer?:
    | false
    | {
        wait?: number;
        maxWait?: number;
        leading?: boolean;
        trailing?: boolean;
      };
}
```

| Option        | Default               | Purpose                                        |
| ------------- | --------------------- | ---------------------------------------------- |
| `storage`     | `window.localStorage` | Inject another synchronous Storage-like target |
| `prefix`      | `"nusm"`              | Namespace all physical keys                    |
| `serialize`   | `superjson.stringify` | Encode state before writing                    |
| `deserialize` | `superjson.parse`     | Decode matching stored values                  |
| `pacer`       | trailing, 50 ms       | Control write scheduling                       |

## Custom namespace and serializer

```ts
const adapter = createLocalStorageAdapter({
  prefix: "acme-state",
  serialize: JSON.stringify,
  deserialize: JSON.parse,
  pacer: { trailing: true, wait: 150 },
});
```

The current scheduler uses `wait`, `leading`, and `trailing`; `maxWait` remains in the public type but is not forwarded yet.

Always change serializer and deserializer together. Existing values written in another format need an explicit migration or a compatible decoder.

## External updates and synchronization

The adapter can translate browser `storage` events into `set` or `remove` events.
nusm continues attaching that adapter listener whenever it is provided.
Authenticated browser synchronization is configured independently through
`sync`; see [Authenticated synchronization](/docs/concepts/synchronization).
Remote values pass the receiving store validator and persist without echoing.

## Constraints

- Browser storage is synchronous; keep values reasonably small.
- Quota and privacy-mode failures reach `onError`.
- Any script on the same origin can read local storage. Do not put secrets there.
- Construct the default adapter only where `window.localStorage` exists.
